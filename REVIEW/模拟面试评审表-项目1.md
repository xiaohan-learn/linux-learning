# 模拟面试评审表 · 简历项目1（V4L2 摄像头）

> 用途：**全真模拟面试时自己打分**。手机录音 → 按六段串讲 → 回放对照本表逐项勾 → 算总分。
> 配套：`面试讲稿-项目1_V4L2摄像头.md`（32题+红榜8题，答案在那）、`M4-V4L2摄像头项目.md`（坑位8条）。
> 打分纪律：**诚实打分**——"心里知道但没讲出来"= 0 分。面试官只听你嘴上说的，不看你脑子里想的。

---

## 一、六段串讲评分表（每段 10 分，共 60 分）

### 第 1 段：30 秒项目概述（10 分）

**时间红线：≤ 40 秒**（超过就扣分，面试官的注意力有限）

| 得分点 | 分值 |
|--------|------|
| 一句话说清"基于 RK3568 的 V4L2 摄像头采集项目" | 2 |
| mmap 零拷贝 + 8 步 ioctl | 2 |
| YUYV 整数定点转 RGB + libjpeg 存 jpg | 2 |
| 条件编译切真假帧源（可测试性） | 2 |
| 生产者消费者 + 环形队列解耦 + 100帧/valgrind 数据 | 1 |
| 收尾"上板只切宏和节点，业务代码不改" | 1 |

**扣分**：超过 40 秒（-2）；把细节摊开讲成 1 分钟（-3）；漏掉"解耦"这个关键词（-2）

---

### 第 2 段：采集流程 8 步 + 两个必考坑（10 分）

**时间：60-90 秒**

| 得分点 | 分值 |
|--------|------|
| 8 步顺序一步不差（open→QUERYCAP→S_FMT→REQBUFS→QUERYBUF+mmap→QBUF→STREAMON→DQBUF循环→STREAMOFF/munmap/close） | 4 |
| **坑1**：S_FMT 后读回真实宽高/格式（驱动会改写请求） | 2 |
| **坑2**：DQBUF 后必须 QBUF 归还，短帧分支也要归还 | 2 |
| `requestbuffers`（count/type/memory，无 offset）vs `v4l2_buffer`（index/bytesused/m.offset）分清 | 2 |

**扣分**：漏任一个必考坑（-2/个）；把 offset 记到 requestbuffers 里（-2）

---

### 第 3 段：处理链——定点转换 + jpeg 九步（10 分）

**时间：60-90 秒**

| 得分点 | 分值 |
|--------|------|
| 定点化因果链：系数×256 → 整数乘法 → >>8 还原（讲出"为什么右移8位"） | 3 |
| **红跟 V、蓝跟 U**（`r_off=359*v`、`b_off=454*u`、`g_off=88*u+183*v`） | 2 |
| 真摄像头要换 BT.601 limited-range 系数（画面发灰的根因） | 2 |
| jpeg 九步顺序（`jpeg_std_error(&jerr)` 挂错误第一步、逐行 `write_scanlines`） | 2 |
| 字段名拼写正确（`image_width`/`input_components`/`jpeg_write_scanlines` 带 s） | 1 |

**扣分**：说"防卡顿"不讲 FPU（-1）；R/B 系数对调（-2，你默写时真错过）；字段名口述拼错（-1）

---

### 第 4 段：多线程——架构 + 三条红线 + 真并行证据（10 分）

**时间：60-90 秒**

| 得分点 | 分值 |
|--------|------|
| 架构：采集线程→4槽环形队列(mutex+not_empty/not_full)→编码线程 | 2 |
| **红线1**：消费者退出判断后有 `break`（否则 count 变负死循环） | 2 |
| **红线2**：帧 `memcpy` 拷进槽位（否则被下一帧覆盖，5张图全一样） | 2 |
| **红线3**：编码在解锁后进行（否则失去并行意义） | 2 |
| 100帧不丢 + valgrind 0泄漏 + `user>real` 证明真并行 | 2 |

**扣分**：把"复用缓冲坑"（Q25）当成"最印象深刻的坑"（Q22）讲（-2，你 11/27 真错过）；说"join 两个 cond"（-1，应为 join 两个线程）；说"real≈user 说明单线程"（-2，你 11/28 真讲反过）

---

### 第 5 段：硬件选型——RK3568 + 2+32G + UVC（10 分）

**时间：60-90 秒**

| 得分点 | 分值 |
|--------|------|
| RK3568 与 RK3566 项目能力等价，差异在资料生态 + 安防岗位对口 | 3 |
| 2+32G 够用论证：单帧 614KB，2GB 内存富余，32GB 装系统+工具链+存图 | 3 |
| UVC 即插即用（Linux 标准驱动、直接出 `/dev/video*`） | 2 |
| MIPI 不选的原因：要适配设备树 + 配 ISP，增加调试成本 | 2 |

**扣分**：只背参数不讲取舍逻辑（-2）；为"2G 不是 4G"心虚（-1）

---

### 第 6 段：踩坑——"AI 代码也有 bug"（10 分）

**时间：45-60 秒**

| 得分点 | 分值 |
|--------|------|
| 明确点题：从别的 AI 搜来代码跟着敲，review 出 **5 个 bug** | 2 |
| 能举 2-3 个具体例子（`uint8_t rgb` 少 `*`、malloc 失败没 return、`y1=p[1]` 应为 `p[2]`） | 3 |
| 自己写 camera 又手滑 3 处（`jpeg_create_ccompress`、`cinfo.jpeg_height`、`iotcl`） | 2 |
| 结论：**过手敲 + 逐行审查 + 编译验证，比"AI 说对"可靠；编译器是最便宜的审查员** | 3 |

**扣分**：答成"复用缓冲坑"（-6，这不是本题）；只说"遇到 bug 就 debug 解决了"没细节（-4）

## 二、红线清单（说了就扣分，都是从你真实踩坑里提炼的）

| # | 错误说法 | 正确说法 |
|---|---------|---------|
| 1 | "R 用 U、B 用 V"（系数对调） | **红跟 V、蓝跟 U** |
| 2 | "mmap 失败判 NULL" | 判 **`MAP_FAILED`** |
| 3 | `cap.capabilities & V4L2_BUF_TYPE_VIDEO_CAPTURE` | **`V4L2_CAP_VIDEO_CAPTURE`**（能力标志 ≠ 缓冲区类型） |
| 4 | 短帧检查 `w*h*3` | YUYV 是 **`w*h*2`** |
| 5 | `memset(buf, 0, sizeof(buf))`（buf 是指针） | **`sizeof(*buf)`** |
| 6 | "V4L2 不能 read" | read 可用但多一次拷贝，主流选 mmap |
| 7 | "join 两个 cond" | join 两个**线程** |
| 8 | "real≈user 说明单线程" | user>real 才证明多核并行；user≤real 是常态 |
| 9 | `cinfo.image.width` / `input_commponents` / `fclose(fd)` | `image_width` / `input_components` / `fclose(fp)` |
| 10 | "第三次握手带数据有风险"（M3 项目2） | 第三次能带，有风险的是第一次 SYN |
| 11 | "四进程组"（M3 项目2） | **四元组** |
| 12 | "ONESHOT 确保一个线程只操作一个 fd"（M3 项目2） | 主客体反了：**一个 fd 只被一个线程操作** |

> 这 12 条里，1-9 是 M4 的、10-12 是 M3 项目2 的。前 9 条你都真踩过——**面试时说错任何一条，等于亲口承认这块没吃透**。

## 四、全真模拟执行流程

1. **环境**：手机录音，找个安静地方，**假装对面坐着面试官**，不要用讲稿
2. **开场**：主动说"我介绍一下项目1"→ 讲第 1 段（30 秒概述）
3. **等追问**：每段讲完后停下来 3 秒（模拟面试官反应），再主动进下一段
4. **六段顺序**：概述 → 采集流程 → 处理链 → 多线程 → 硬件 → 踩坑
5. **回放**：逐段对照本表打分，**卡壳超过 3 秒的地方标红**
6. **记录**：把扣分点和标红写进下方自评记录，针对练
